# 블로그 영어·일본어 번역

한국어 포스트를 기준으로 같은 파일명의 영어·일본어 포스트를 생성한다. 사용자가 언어를 제한하지 않으면 두 언어를 모두 처리한다. 이 스킬은 에이전트 작업 절차이며 백그라운드 감시나 예약 작업이 아니다.

## 입력과 범위

- 현재 작업 중인 한국어 포스트 또는 사용자가 지정한 파일·제목·URL을 사용한다. URL은 로컬 원문과 대응시킨다. 대상이 불명확할 때만 질문한다.
- 원문은 `content/ko/posts/<filename>.md`, 번역은 `content/en/posts/<filename>.md`와 `content/ja/posts/<filename>.md`에 둔다. 실행 전 `hugo.yaml`의 언어 설정을 확인한다.
- 한국어 글 작성 작업에서는 원문의 셀프 리뷰가 끝난 뒤 번역을 함께 생성한다. 사용자가 한국어만 요청하거나 번역을 나중으로 미루면 그 지시를 따른다.
- 원문 수정 후에는 해당 수정과 연결된 번역도 갱신한다. 무관한 글을 일괄 번역하거나 커밋·푸시하지 않는다.

## 번역 전 확인

원문 전체와 같은 파일명의 기존 번역, 각 언어의 최근 포스트를 읽는다. 기존 번역에 사용자의 미커밋 수정이 있으면 보존하면서 필요한 부분만 갱신한다. 변경 의도가 충돌하여 판단할 수 없을 때 질문한다.

한국어 원문을 기준으로 의미와 구조를 보존한다. 번역 과정에서 주장을 강화하거나 새로운 사례·수치·출처를 추가하지 않는다. 사실관계에 의문이 생기면 원문과 번역에 서로 다른 결론을 넣지 말고 문제를 보고한다.

## 번역 규칙

- 제목, 설명, 본문, TL;DR, 표, 이미지 설명, 각주의 설명을 모두 번역한다. 문단별 의미, 제목 계층, 목록과 서술형의 구분을 유지한다. 요약으로 대체하지 않는다.
- 영어는 짧고 자연스러운 기술 블로그 문장으로 쓴다. 일본어는 기존 대상 글의 문체를 유지한다. 새 글은 인접 포스트의 문체를 확인하며, 별도 지시가 없다면 기존 사이트에서 사용하는 자연스러운 です・ます체를 기본으로 한다.
- `date`, `draft`, `toc`, `tags`, `images` 등 언어와 무관한 frontmatter는 원문과 일치시킨다. `title`, `description`처럼 독자에게 보이는 텍스트는 번역한다. 기존 `translationKey`가 있으면 공유하고, 임의로 새 키를 만들지 않는다.
- 파일명, 코드 식별자, 명령어, 경로, 외부 출처 URL, 각주 번호를 유지한다. 코드 예시는 실행 의미를 바꾸지 않는다. Hugo shortcode의 구문과 이미지 경로를 보존하고 독자용 캡션만 번역한다.
- 저자 사진은 `/posts/images/Dohyun.png`를 사용한다. 영어 저자 표기는 `Dohyun Jung - Principal Consultant, ROBOCO`, 일본어는 `チョン・ドヒョン - ROBOCO首席コンサルタント`로 맞춘다.

## 내부 링크

- 링크 대상의 실제 파일과 `draft`, `slug`, `url`을 확인한다. 같은 언어의 발행 가능한 대응 글이 있으면 그 제목과 링크를 사용한다. 언어별 경로를 추측해 접두사만 붙이지 않는다.
- 기존 `relref`는 현재 언어의 올바른 글로 해석되는지 확인한다. 번역이 없는 글은 발행된 한국어 원문으로 연결하고 링크 설명에 한국어 자료임을 표시한다.
- 대상이 초안이면 공개 사이트에서 열리지 않을 수 있음을 보고한다. 링크를 만들기 위해 대상 글을 임의로 발행하거나 새로 번역하지 않는다. 일반 빌드를 깨뜨리는 미해결 `relref`도 만들지 않는다.
- 특정 제목으로 이동하는 앵커는 번역 후 생성된 HTML에서 확인한다. 한국어 앵커를 영어·일본어 페이지에 그대로 복사하지 않는다.

## 검증과 전달

1. 세 언어를 대조해 문단·TL;DR·예시·각주 누락, 수치 변경, 번역되지 않은 한국어 문장, 문체 혼용을 확인한다. 고유명사와 한국어 자료 제목은 문맥에 따라 허용한다.
2. 일반 Hugo 빌드를 임시 출력 경로로 실행한다. 원문이 초안이면 `-D` 빌드도 실행한다. 빌드 오류를 수정하고 생성된 HTML에서 세 언어 페이지와 언어 전환 링크, 내부 링크를 확인한다.
3. 원문과 번역의 발행 상태·날짜·태그 및 각주 참조와 정의의 대응을 점검한다. 빌드 성공만으로 번역 품질이나 공개 링크의 존재를 보장한다고 말하지 않는다.
4. 생성·갱신한 파일 링크와 검증 결과를 짧게 알린다. 해결하지 못한 초안 링크나 원문 문제는 함께 밝힌다. 현재 요청에 커밋·푸시 권한이 포함되어 있을 때만 수행한다.
