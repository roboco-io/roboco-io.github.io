## **로보코가 만드는, 바이브 코딩 시대의 도구들**

로보코는 컨설팅과 교육 현장에서 얻은 통찰을 자체 프로덕트로 발전시킵니다. 모두 누구나 사용할 수 있도록 공개하고 있으며, 의견과 기여를 환영합니다.

이 페이지에서는 실무에 활용할 도구와 방법론을 소개합니다. 연구·실험의 질문과 결과는 [Research](/research/)에서, 강의·워크숍 자료는 [Education](/education/)에서 확인할 수 있습니다.

## **The Software Factory**

> *의도를 정책과 실행계획으로, 결과를 증거로, 피드백을 개선으로.* — 소프트웨어 팩토리와 AI 시대의 조직 설계.

『The Software Factory — 소프트웨어 팩토리와 AI 시대의 조직 설계』는 소프트웨어 조직 리더를 위한 한국어 책입니다. 의도를 정책과 실행계획으로 구체화하고, 수행 결과를 증거로 검증하며, 피드백으로 정책과 계획을 개선하는 개발 접근법을 패턴 언어로 설명합니다. 현재 공개 초안으로 웹에서 읽을 수 있으며, GitHub 이슈로 의견을 받습니다.

함께 공개한 **The Software Factory Demo**는 이 접근법의 구현 예제입니다. 사람이 원하는 변화를 글로 요청하면 AI가 구현하고 검증한 뒤 실제 서비스(RealWorld 예제 블로그)에 반영하는 과정을 누구나 관찰할 수 있습니다. 반복되는 실패를 바탕으로 팩토리의 작업 규칙을 고치는 자가 개선의 개념 검증도 함께 수행합니다.

### 이런 분에게 유용합니다

- AI 시대에 개발 조직의 역할과 프로세스를 다시 설계하려는 리더
- 소프트웨어 팩토리가 실제로 어떻게 동작하는지 직접 보고 싶은 분
- 요청·검증·배포·자가 개선이 연결된 구현 사례를 참고하려는 팀

### 링크

- 책 읽기: [factory.roboco.io](https://factory.roboco.io)
- 데모 서비스: [roboco.io/the-software-factory-demo](https://roboco.io/the-software-factory-demo/) · [팩토리 대시보드](https://roboco.io/the-software-factory-demo/factory/)
- GitHub: [roboco-io/the-software-factory](https://github.com/roboco-io/the-software-factory) · [roboco-io/the-software-factory-demo](https://github.com/roboco-io/the-software-factory-demo)

## **Intent Engineering**

> *Ship intent, not code.* — 의도를 명확히 기록하고, 나머지는 AI에게 위임하는 바이브 코딩 패러다임.

코드를 직접 작성하던 시대에서 AI에게 의도를 전달하는 시대로 넘어가는 지금, "무엇을 왜 만드는가"를 정확히 표현하는 일이 가장 중요한 작업이 되었습니다. Intent Engineering은 이 의도를 문서로 정리하고, 진화시키며, 팀과 공유하기 위한 실용적 방법론입니다.

### 이런 분에게 유용합니다

- AI에게 일을 위임하면서 의도가 흐릿해지는 경험을 한 분
- 프로젝트의 "왜"를 잃어버리지 않고 빠르게 만들고 싶은 분
- 팀 내에서 AI 협업의 공통 언어를 정착시키고 싶은 리더

### 링크

- 사이트: [intent.roboco.io](https://intent.roboco.io/ko/)
- GitHub: [roboco-io/intent-engineering](https://github.com/roboco-io/intent-engineering)

## **VAF — Vibe Adoption Framework**

> *바이브 코딩, 어디서부터 어떻게 도입할 것인가.* — 기존 기업이 에이전트 중심 개발 체제로 전환하는 여정을 구조화한 프레임워크.

도구를 몇 개 도입한다고 개발 방식이 바뀌지는 않습니다. VAF는 로보코가 바이브 코딩·AX 컨설팅 현장에서 축적한 베스트 프랙티스를 정리해, 이미 자리 잡은 조직이 무엇을 먼저 점검하고 어떤 순서로 전환해야 하는지를 보여줍니다.

- **3가지 관통 원칙**: 에이전트는 인력 레버리지다 · 오너십은 사람에게 남는다 · 인지 부채는 관리되어야 한다
- **6가지 관점**: 전략 · 인력과 오너십 · 거버넌스와 가드레일 · 에이전트 환경 · 지식 · 하네스 엔지니어링 (26개 역량 항목)
- **4가지 전환 영역**: 코드 생산 · 품질 보증 · 지식 · 조직과 역할
- **4단계 도입 여정**: 준비 → 진단 → 파일럿 → 전환

### 이런 분에게 유용합니다

- 조직 차원의 바이브 코딩 도입을 설계해야 하는 CTO·엔지니어링 리더
- 파일럿은 성공했지만 전사 확산에서 막힌 팀
- AI 도입의 진행 상황을 역량 단위로 진단하고 싶은 조직

### 링크

- 사이트: [vaf.roboco.io](https://vaf.roboco.io/ko/)
- GitHub: [roboco-io/vibe-adoption-framework](https://github.com/roboco-io/vibe-adoption-framework)

## **VDLC — Vibe-Driven Development Lifecycle**

> *의도와 컨텍스트가 1차 산출물이고, 코드는 그로부터 재생성 가능한 2차 산출물이다.* — 바이브 코딩을 전제로 다시 세운 소프트웨어 개발 생명주기.

기존 SDLC의 구현 단계에 AI를 끼워 넣는 방식으로는 한계가 분명합니다. VDLC는 AI 에이전트가 구현의 주체가 되는 상황을 처음부터 전제하고, 개발 전 과정을 다시 설계한 라이프사이클입니다.

- **6가지 원칙**: 의도가 소스다 · 인간은 판단하고 AI는 실행한다 · 속도는 검증이 결정한다 · 컨텍스트는 자산이다 · 작게 돌리고 자주 환류한다 · 이해가 소유다
- **6단계 라이프사이클**: 의도 정의 → 컨텍스트 설계 → 공동 구현 → 검증 → 배포와 관찰 → 환류
- **주간 사이클**: Shape Up을 바이브 코딩 전제로 재해석한 팀 운영 리듬(4일 빌드 + 1일 쿨다운)
- **실무 자산**: 단계별 플레이북, 문서 템플릿, 성숙도 모델, 도입 로드맵, 측정 지표

### 이런 분에게 유용합니다

- AI가 코드를 쓰는 팀에서 프로세스와 관문을 다시 정의해야 하는 리더
- 스프린트·리뷰·QA 등 기존 개발 리듬이 더 이상 맞지 않는다고 느끼는 팀
- 컨텍스트와 문서를 팀 자산으로 관리하는 방법을 찾는 조직

### 링크

- 사이트: [vdlc.roboco.io](https://vdlc.roboco.io/ko/)
- GitHub: [roboco-io/vibe-driven-development-lifecycle](https://github.com/roboco-io/vibe-driven-development-lifecycle)

## **VibeMap**

> *아이디어에서 배포까지, 바이브 코딩의 전체 지도.* — 의도공학·Claude Code·Git·TDD·AWS 서버리스 등 60여 개 개념을 인터랙티브 그래프로 탐색.

바이브 코딩 생태계는 빠르게 확장되고 있고, 어디서부터 무엇을 익혀야 할지 막막한 경우가 많습니다. VibeMap은 핵심 개념들과 그 관계를 한 장의 인터랙티브 지도로 보여주어, 학습자와 팀이 자기 위치와 다음 길을 찾을 수 있도록 돕습니다.

### 이런 분에게 유용합니다

- 바이브 코딩을 처음 시작하며 학습 경로를 잡고 싶은 분
- 팀의 도구·프로세스·역량 매핑이 필요한 리더
- 강의나 워크숍에서 시각적 레퍼런스로 활용하고 싶은 강사

### 링크

- 사이트: [vibemap.roboco.io](https://vibemap.roboco.io)
- GitHub: [roboco-io/vibemap](https://github.com/roboco-io/vibemap)

## **token-forge**

> *오픈웨이트 모델을 우리 AWS 계정에서 운영하는 코딩 에이전트용 LLM 인프라.*

token-forge는 AWS CDK로 EC2 Spot GPU와 vLLM 서빙 환경을 구성하는 오픈소스 도구입니다. OpenAI·Anthropic 호환 API를 제공해 Claude Code 같은 코딩 에이전트를 연결할 수 있습니다. 사용하지 않을 때 GPU를 종료하고, Spot 가용성을 바탕으로 실행 리전을 선택하는 운영 기능도 갖추고 있습니다.

### 이런 분에게 유용합니다

- 코드와 프롬프트를 외부 LLM API로 보내기 어려운 팀
- 대량의 토큰을 집중적으로 사용하는 개발팀
- AWS GPU 인프라를 직접 운영할 수 있는 조직

Spot 인스턴스가 회수되면 서비스가 잠시 중단될 수 있으며, 첫 실행에는 AWS GPU Spot 할당량이 필요합니다. 상시 가용성이 필요한 서비스보다는 개발과 배치 작업에 적합합니다.

### 링크

- GitHub: [roboco-io/token-forge](https://github.com/roboco-io/token-forge)

## **Vibe Up**

> *Shape Up for the Vibe-Coding Era.* — 구현 비용이 0에 수렴해도 병목은 사라지지 않고 이동합니다.

Vibe Up은 Basecamp의 Shape Up(Ryan Singer)을 바이브 코딩 시대에 맞춰 재구성한 가이드입니다. 구현 비용이 급격히 낮아진 뒤 새로 생긴 병목인 검증·리뷰, 주의력·집중, 복잡도 부채를 짚습니다. 이어서 애피타이트와 셰이핑이라는 원작의 원리가 예산 단위만 바꿔 유지되는 과정을 설명하고, [VDLC](https://vdlc.roboco.io)의 주간 사이클(4일 빌드 + 1일 쿨다운)로 연결합니다. 한국어·영어·일본어로 제공합니다.

### 이런 분에게 유용합니다

- Shape Up을 운영해 왔지만 AI 도입 후 사이클과 베팅 기준이 맞지 않게 된 팀
- 바이브 코딩 환경에서 기획(셰이핑)과 검증의 역할을 다시 정의하려는 리더

### 링크

- 사이트: [vibeup.roboco.io](https://vibeup.roboco.io/ko/)
- GitHub: [roboco-io/vibeup](https://github.com/roboco-io/vibeup)

## **AI Doc Ready**

> *사람과 AI가 함께 읽기 쉬운 보고서로.* — Markdown·HWPX 보고서 구조 검사 도구.

AI Doc Ready(`aidocready`)는 Markdown과 HWPX 보고서가 AI 친화적 작성 원칙을 따르는지 검사하는 CLI입니다. 행정안전부의 AI 친화적 보고서 도입 발표에서 제시한 원칙(표·그림 상단 제목, 단순한 셀 병합, 서술식 문장 등)을 실제 문서 작성 과정에 적용하는 데서 출발했습니다. 구조 검사는 재현 가능한 코드로 수행하고, 문장의 명확성과 의미 보존은 원문 대조와 수동 검토로 확인하도록 역할을 나눕니다. HWPX 파싱은 오픈소스 라이브러리 Kordoc을 사용합니다.

### 이런 분에게 유용합니다

- 공공기관 또는 공공 사업 보고서를 HWPX로 작성하는 분
- AI가 보고서를 정확히 읽고 요약하도록 문서 구조를 정비하려는 팀

### 링크

- 제품 페이지: [roboco.io/aidocready](https://roboco.io/aidocready/)
- 실행: `npx aidocready lint report.hwpx`
- GitHub: [roboco-io/aidocready](https://github.com/roboco-io/aidocready)

## **오픈소스 도구와 리소스**

프로젝트 준비, 문서 변환, AI 에이전트 활용을 돕는 도구와 학습 자료를 GitHub에 공개하고 있습니다. 로보코의 컨설팅·교육 현장에서 다듬어 온 도구와 큐레이션을 각자의 업무에 활용할 수 있습니다.

### **roboco-cli**

Claude Code와 바이브 코딩을 위한 AI-네이티브 개발 스캐폴딩 CLI. 로보코의 컨설팅 방법론 — 어떻게 프로젝트를 시작하고, AI 에이전트가 잘 작업할 수 있도록 저장소를 구조화하는지 — 을 명령어 한 줄로 압축한 도구입니다.

- GitHub: [roboco-io/roboco-cli](https://github.com/roboco-io/roboco-cli)

### **awesome-vibecoding**

바이브 코딩의 리소스·튜토리얼·베스트 프랙티스·예제를 모아둔 awesome 큐레이션 리스트. 한국·해외 자료를 폭넓게 다루며, 새로 등장하는 도구와 사례를 지속적으로 반영합니다.

- GitHub: [roboco-io/awesome-vibecoding](https://github.com/roboco-io/awesome-vibecoding)

### **hwp2md**

HWP(한글 워드프로세서) 문서를 LLM이 다룰 수 있는 Markdown으로 변환하는 도구. 한국 비즈니스 환경에서 AI를 도입할 때 가장 먼저 마주치는 문서 호환성 문제를 해결하기 위해 만들었습니다.

- GitHub: [roboco-io/hwp2md](https://github.com/roboco-io/hwp2md)

### **plugins**

Claude Code의 사용성을 확장하는 Skills·Commands·Agents·Hooks 플러그인 모음. 로보코가 컨설팅·교육 워크플로우에서 다듬어 온 패턴을 누구나 설치해 쓸 수 있도록 정리해 두었습니다.

- GitHub: [roboco-io/plugins](https://github.com/roboco-io/plugins)

### **claude-wiki**

Claude Code로 코드베이스의 에이전트 친화적 위키를 생성하고 유지하는 도구. 위키 생성 로직은 Claude Code 플러그인으로 동작하므로, 별도 API 키 없이 기존 Claude 구독 안에서 실행됩니다. 터미널과 CI에서는 얇은 CLI 래퍼(`claude-wiki`)로 같은 로직을 실행합니다.

- GitHub: [roboco-io/claude-wiki](https://github.com/roboco-io/claude-wiki)

### **DORA AI Guide**

DORA(dora.dev)의 AI 관련 리서치를 한국어와 일본어로 요약한 비공식 학습 가이드. 4대 리포트, AI Capabilities Model의 7대 역량, 12편의 인사이트를 정리해 AI 도입 효과를 근거로 논의할 때 참고할 수 있습니다.

- 사이트: [roboco.io/dora-ai-guide](https://roboco.io/dora-ai-guide/)
- GitHub: [roboco-io/dora-ai-guide](https://github.com/roboco-io/dora-ai-guide)

### **vibe-ready-cli**

내 저장소가 바이브 코딩(AI 에이전트 기반 개발)에 얼마나 준비되어 있는지 한 명령으로 점검해 주는 CLI. Claude Agent SDK 또는 Codex CLI로 LLM이 직접 저장소를 탐색하고 7개 카테고리에 점수를 매긴 뒤, 종합 등급과 구체적인 개선 권장 사항을 제시합니다(`npx vibe-ready .` 로 즉시 실행 가능).

- GitHub: [roboco-io/vibe-ready-cli](https://github.com/roboco-io/vibe-ready-cli)

### **ghx-cli**

공식 GitHub CLI(`gh`)가 다루지 못하는 영역을 채우는 확장 CLI. GitHub Projects v2의 뷰·워크플로·필드 관리와 GitHub Discussions CRUD를 GraphQL API로 직접 조작할 수 있게 해 줍니다(`ghx project`, `ghx item`, `ghx field`, `ghx view` 등). 프로젝트 관리 자동화·일괄 처리·템플릿 적용 같은 실무 시나리오를 한 명령으로.
